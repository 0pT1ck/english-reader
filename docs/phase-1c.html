§1

为什么推倒重来

P1b 的数据质量其实不差。推倒的理由不是它错了，是我们无法知道它对不对。

P1b 的三层验证查了三件事：义项数是否合理、英文定义用词是否超纲、词在不在真题里。 没有一项能回答「这个词有没有漏掉一个常用义项」。模型少给一个义项，系统永远不知道， 而少给的那个恰恰可能是考试要考的。

抽查 address 的结果是好的——我们给的三个义项（地址／着手解决／演说）， 在 Wiktionary 剔除古义后的 20 条清单里全都对得上，也没落下该学的。但一个词的抽查不是证据， 而且这正说明问题：要知道有没有漏，就得有个清单可比。

所以这一阶段引入外部清单。不是因为模型不可信，是因为没有参照系的判断无法被检验。

§2

三步分工

每一步都交给最有资格回答的那一方，模型只做它擅长的判断。

Wiktionary 全量转储（502 MB，一次下载，离线可重跑）
  ↓  清单：这个词在英文里存在哪些概念
按标签机械过滤 obsolete / archaic / dated / rare / dialectal
  ↓  免费，address 从 29 条降到 20 条
LLM 做语域筛选：哪些属于通用书面英语，哪些是行话
  ↓  高尔夫术语、内存地址、航海用语出局
LLM 按我们的判据合并成中等粒度，并重写英文定义与中文投影
  ↓  address 20 条 → 3 项
真题标注：每个义项在 452 篇里出现几次
  ↓  优先级，以及熟词僻义的自动标记

模型不回答「值不值得学」——这一条是关键

最初的设计是问模型「这几条里哪些是四六级考生需要掌握的」。这个问法会毁掉整条管线， 因为它会答出最常见的意思，而四六级恰恰考不常见的那个。

address 就是活例子：按那个问法，模型多半保「地址」、可能保「演说」， 而「着手解决」因为不那么常用会被筛掉。但真题里出现的偏偏是它—— a problem that needs to be addressed immediately。 最该学的义项会被当成不重要的删掉。

所以模型只回答一个客观得多、也不需要它猜考纲的问题：

这个义项属于通用书面英语，还是某个专门领域的行话／已经不再使用的古义？

删除的理由永远是语域，不是「不重要」。「着手解决」是通用书面英语，留下。 高尔夫的 address the ball 是行话，删掉。这个判断模型做得稳，因为它不涉及价值排序。

优先级完全交给真题

一个义项在 452 篇真题里出现过，它就是要掌握的，不管模型觉得它常不常用。 这是这个项目里唯一真正锚定目标的证据，主文档 F5 早就写了这条原则： 「一个词在近二十年真题里出现 50 次，比它在某份词表里被标成 CET-4 有说服力得多。」

§3

熟词僻义变成可以算出来的

意外收获

这一层是讨论中途冒出来的，不在原计划里，但可能是整个 P1c 最有价值的产出。

跑完管线，每个义项会同时带上两个数：模型给的常用度序号，和真题里的实际出现次数。 两者一交叉，熟词僻义就自己浮出来了：

词义项序号真题出现判定
address地址1有常见义，正常
address着手解决2有熟词僻义 — 序号靠后却被考到
address演说3无存着，低优先级

规则一句话：序号靠后、却在真题里出现的义项，就是熟词僻义。 这正好填进 senses 表里 P0 建表时预留、至今为空的 is_exam_key 字段。

主文档 §C 写着「熟词僻义正是 CET 阅读最爱考的地方」——那一直只是一句设计理念， 现在它变成一个能算出来的标记，以后出抽查题、排复习顺序都能直接用。

顺带还能纠错：如果某个义项模型排第 4、真题里却出现最多，那是模型排错了，真题说了算。

§4

Wiktionary 怎么用

只取清单，不取措辞

Wiktionary 的英文定义不能直接用。它大量条目是 1913 年韦氏词典的公版文本， 语言是一百年前的：to superscribe, or to direct and transmit、to betake、 to make suit to as a lover。对 CET 学习者这是负资产，比我们模型写的还难。

所以取它的义项清单（这个词在英文里存在哪些概念），英文定义由模型按我们的 2000 词规格重写。

附带好处：不复制它的文字，就不触发 CC BY-SA 的传染性条款——将来公开仓库没有包袱。 这一点上它比柯林斯干净得多：柯林斯没有合规的批量来源，官方 API 已经 403， 流传的 MDX 是未授权复制，会变成一个「不能公开的依赖」。

取全量转储，不用逐词接口

kaikki.org 两种都能用：逐词 .jsonl（address 23 KB）， 以及 502 MB 的英文全量转储。取转储——7226 个词就是 7226 次请求， 而转储下一次就永久离线可用，重跑不依赖网络，也不给对方添麻烦。

先做一次覆盖率体检

这是动手前的第一步，也是可能推翻方案的一步。Wiktionary 对我们这批词的覆盖率还没测过。 如果覆盖率高（预期如此，都是常用词），继续；如果发现大片缺失，整个方案要重想。

§5

粗筛换掉

P1b 的粗筛在数中文逗号，这件事本身就和我们的原则拧着。

现在的判据是：数 ECDICT 中文释义里有几个词性标记、几条逗号分隔的说法。 用中文释义的结构去猜英文有几个概念——而我们自己的第一原则是「义项按英文概念划分， 不按中文差异划分」。

实测它的准确度：

粗筛归类词数实际平均义项结果只有 1 个
多词性 · 强候选14372.9858（4%）
双词性 · 待判17892.14310（17%）
单词性多义3602.01102（28%）

整体 13% 白建。而且阈值（3 词性／2 词性／7 条释义）是拍出来的—— 当初为了让总数落在方案估算附近调的，没有证据支撑。

更麻烦的是看不见的那一半：被判成「简单」直接跳过的 3640 个词里， 有多少其实是多义的？现在完全是盲区。而且判据依赖 ECDICT 每个条目的编写风格—— 同样的多义程度，编得详细的被建、编得简略的被跳过，这不是词的性质，是编者的习惯。

换成 Wiktionary 的义项数当过筛信号：它直接就是「英文里有几个概念」，不用从中文反推， 而且是免费的（不调模型）。这一步顺带把 3640 个词的盲区扫掉。

§8

§9

推进顺序

前三步都是免费的，而且任何一步的结果都可能改变后面的方案。

1下转储，测覆盖率 7226 个词里 Wiktionary 有多少、平均几个义项、标签过滤后剩多少。 覆盖率太低就得重想方案。免费。
2重新过筛 用义项数替代数中文逗号，看那 3640 个被跳过的词里盲区有多大。免费。
3差异审计 现有 3587 个词，Wiktionary 有而我们没有的义项有多少。 这个数直接决定重建值不值。免费。
4小样本横评 30 个词 × 几个模型，测 §8 里那三个不确定：粒度会不会失控、 会不会按词性拆、哪个模型合适。几毛钱。
5全量重建 7226 个词。前四步的结果决定提示词和模型怎么定。
6真题标注 产出每个义项的考频、熟词僻义标记，以及漏义项报告。

第 1 到 3 步跑完应该停下来一起看数。 如果差异审计发现我们几乎没漏，那「全量重建」的性价比就要重新算—— 可能只补漏、只加真题标注，比推倒重来划算得多。

§11

实际怎么走的 —— 重建搁置，先补全

2026-09-06

前三步全部跑完，第四步撞墙。结论是：外部清单确实有价值， 但让模型按清单重建的粒度控制没做通，不值得继续卡在这里。

前三步：两个结论，一个方法错误

覆盖率 99%（7171/7226），7 万个义项条目，14% 带 obsolete/archaic 标签可免费剔除。 数据源没问题。

盲区确认了，而且很大。被原粗筛判成「简单·跳过」的 3640 个词里， 65% 其实是多义词——bank、come、do、 be、positive 全在里面。数中文逗号这个判据确实不行。

第三步的方法是错的。原计划「比义项数，差得多就说明漏了」—— 我们平均 2.47、Wiktionary 12.29，run 是 6 对 113。 但这什么也证明不了：Wiktionary 把「跑一家公司」「板球得一分」「养鸡场围栏」 都算独立义项，粒度不在一个量级。数量差只能证明两者切法不同， 要回答「有没有漏」必须逐条做语义匹配。

第四步：粒度控制没做通

做法平均义项定义难词/条说明
P1b 老办法（无清单）2.460.61粒度合格
给清单 · deepseek-flash7.00.18出现重复义项
给清单 · mimo-v2.5-pro5.00.20无重复，但仍偏高

§8 里担心的三件事，两件没发生、一件发生了： 按词性拆没发生（自动检测 0 例）；定义反而更简单了，难词密度 0.61 → 0.18； 粒度失控发生了。

改了三轮提示词——点名语域反例、禁止清单外自创、给每个词按清单长度算出目标项数—— deepseek 从 6.8 只降到 7.0，还开始产出重复义项：fast 出现两次「禁食/斋戒」， address 同时给出「演说/讲话」和「向…讲话/向…致辞」。

诊断：这不是拆太细，是语义聚类没做对。P1b 的任务是「看中文释义写义项」， 这里是「读 25 条清单做聚类再改写」——后者难得多，快模型到了能力边界。 换 mimo 立刻降到 5.0 且无重复，但仍高于设计目标，而且慢 60%。

值得记下的是：合并本身有效

present   把 8 条合并成「提出／展现／介绍」一项   ← 设计判据，通过
bank      河岸保住；内存区块、飞机侧倾被正确删掉
address   熟词僻义「着手解决」每次都在

语域筛选和覆盖追踪都是有效的——问题只在合并力度。所以这条路是通的， 只是需要两步走（先只做聚类、只输出编号分组，再写定义）， 而那是另一轮工程。

决定：先补全，重建留到以后

与其继续在提示词上试错，不如用已经验证过的老办法把缺口补上，把闭环推下去。 外部清单的价值已经证明（盲区那 65% 就是它查出来的）， 工程也留在代码里（wiktionary_senses 表、sense_rebuild 任务、 inventory.py 的分词性截断），随时可以接着做。

§12

第二轮生成 —— P1 完成定义的答案

2026-09-06

P1 的完成定义是「生成的文章用词在范围内、搭配无误、句法是正常书面语」。 这一节把它验证掉，顺带纠正我自己一个判断错误。

先接上 API

原 P1c 的第一件事。generate_article 批量任务：出提示词 → 调模型 → 解析 → 校验 → 入库，复用已有的每一块，八篇零失败。手动模式保留不动。

一个被对照实验推翻的判断

控制变量重跑：同一个模型、同一批目标词，只换提示词措辞。

我为这个数字改了三轮提示词，还差点得出「模型做不到，得靠 P1d 定点修补」的结论。 实际上校验器一直在数别的东西：spaCy 只把 there is/are 里的 there 标成 expl，而 It is clear that… 里的 It 标的是普通 nsubj。P1a 建校验器时我把 expl 直接写成「形式主语」，之后每一轮都在读这个标签，没人回头验证它到底在数什么。

新提示词不但没有「形式主语为零」，反而用到了基线的 1.6 倍—— 那条指令一直是有效的。接近零的是 there be，而它本来就不是要控制的东西。

教训：一个错误的度量比没有度量更危险。它看起来在指导决策，实际在误导决策， 而且因为带着数字，反而没人怀疑。

被动语态：数字约束无效，结构性规则两轮解决

唯一真实的偏差，三个模型都在基线的两倍上。调的过程又验证了一件事： 模型对提示词里的数量约束基本无感——这和义项集那次「让它合并成 3-5 项、结果给 7 项」 是同一个现象。

提示词写法被动对照基线 17.0
「该用就用，不要一律改成主动」30.8被读成「多用被动」
「全文不要超过五六处」（给数字）36.5无效，反而更高
「只在执行者不重要时才用」（给条件）24.6方向对了
再加「找得到具体施动者就改主动」＋ 写完自查15.5达标

说清楚「什么时候该用」，比说「用几次」有效得多。 最终这一版同时把名词化降到 16.3、句长 18.8（基线 18.9）、超纲率 0.14%。

顺延的理由

难度画像和语境释义标注 → P2。两者的消费方都在 P2：难度画像是为了「按你的水平 筛真题给你读」，语境释义标注是三层释义的第一层。在使用它们的功能出现之前先做， 就是在没有反馈的情况下猜格式——这个教训 P1c 前半段刚吃过一次。

择优和定点修补 → P1d。纯工程，没有可行性风险：P1 已经证明模型写得出合格文章， 这两项是把「合格」变成「稳定合格」。但现在每天生成的需求还不存在， 先建等于空转，而且择优的排序标准要看真实使用中什么样的文章更好读——那也得等 P2。

一条没验证的完成定义

P1 的完成定义是「用词在范围内、搭配无误、句法是正常书面语」。 第一和第三条有数据：超纲率 0.14%、被动 15.5 对基线 17.0。

「搭配无误」从来没有独立验证过。原计划是找十几个英语好的人做盲测， 后来决定「如果有学习价值，甚至无需真人测试」，于是这一条实际上只有我读了几篇之后的主观判断。 这不是验证，写在这里是为了别把它当成验证过的事。

最省事的补法是本人读两篇——文章都在 generation_drafts 里。 真要严格，AI 搭配检查的自动化在 P1d 的范围内。
