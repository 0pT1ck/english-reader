请你帮的四件事

我写了一个自用的英语阅读 App，想装到自己手机上。 我没有 Mac，也没有付费的开发者账号——借你的账号走一次 TestFlight 内测。 这四件事做完之后你就不用再管了：以后每个版本我自己传，不需要你点任何东西， 也不用过 Apple 审核。

大概要花你二十分钟，全在 App Store Connect 的网页上，不用开 Xcode。 做完把第 2 步的三样东西发给我就行。
四件事

具体怎么做

1
建一个 App 记录 App Store Connect → 我的 App → 左上角「+」→ 新建 App。
  • 平台：iOS
  • 名称：　　　　　　——在整个 App Store Connect 里是唯一的，撞名了换一个，我准备了备选
  • 主要语言：简体中文
  • 套装 ID：下一步说
  • SKU：随便填一个，比如 english-reader-01，只是你自己的编号
只做内测不需要 App Store 审核，但这条记录必须先有—— 没有它就没有 TestFlight 那一栏。
2
建一把 API 密钥，角色选 Admin 用户和访问 → 集成 → App Store Connect API → 「+」新建密钥。 名字随便，比如 english-reader-ci。
  • 角色必须选 Admin。低一级的角色不能让自动化去申请签名证书—— 那样的话证书每年过期一次，每次都得再麻烦你。Admin 之后这件事就自动了
建好之后把这三样发我：
  • Issuer ID——页面上方那一长串 UUID
  • Key ID——密钥那一行上就有
  • 那个 .p8 文件——只能下载一次， 点了下载就立刻存好，页面刷新之后再也拿不到了
3
把我加成团队成员 用户和访问 → 用户 →「+」邀请。
  • 我的 Apple ID：　　　　　　
  • 角色给 Developer 就够，不用更高
4
把我加进 TestFlight 的内部测试 那个 App → TestFlight → 内部测试 → 新建一组（名字随便，比如「本人」）→ 把我加进去。 这一步做完就结束了。之后我上传的构建几分钟内就能装到手机上， 不过 Apple 审核——内部测试员是免审的，这也是我们走内测而不是公测的原因。
要你定

套装 ID（Bundle ID）

这个得用你的标识，我定不了。

习惯写法是你的域名倒过来加应用名，比如域名是 example.com 就写 com.example.englishreader。没有域名的话用什么都行，只要全球唯一—— 很多人用 com.你的名字拼音.englishreader。

建完之后不能改，所以定了就告诉我一声，我这边要写进构建配置里。

说明

这把密钥有多大权限，以及我怎么保管它

说在前面：Admin 级的密钥权限不小。它能在你的账号下申请和吊销签名证书、 能上传构建、能改 App 的元数据。这是你的开发者身份，不是我的， 所以下面这些我先说清楚，你觉得不合适可以随时喊停。
1它存在 GitHub 的加密 secret 里，不进代码、不进日志。 我的仓库是公开的（为了用免费的 macOS 构建机），但 secret 本身不公开。
2只有我手动触发的任务能用到它。 仓库公开意味着任何人都能提 PR，而同仓库的 PR 是能拿到 secret 的—— 所以用到密钥的那一步只允许我手动点和打版本标签时触发， 任何 PR 都碰不到它。这条是写死在配置里的，不是靠自觉。
3你随时可以作废它。 在建它的那个页面点一下撤销，立刻失效，不影响你账号里别的东西。
4如果你觉得 Admin 太大，还有一条路： 角色降成 App Manager，但那样签名证书要你手动导出给我， 而且一年过期一次，每次都得再找你。我建议 Admin，但你说了算。

收到之后我做什么

这一节是给我自己看的，你不用管。

·三样东西存成 GitHub secrets：ASC_ISSUER_ID、 ASC_KEY_ID、ASC_KEY_P8（base64）
·上传的 job 只接 workflow_dispatch 与 tag 触发。 不能接 pull_request——公开仓库里同仓库的 PR 能拿到 secret
·走 cloud signing：xcodebuild -allowProvisioningUpdates -authenticationKeyPath / -authenticationKeyID / -authenticationKeyIssuerID。 分发签名要求 Admin 级密钥，这就是第 2 步那条要求的由来
·Bundle ID 写进构建配置；App 名字与它必须跟 App Store Connect 里的一致
!这些属于下一个 Phase（界面与上架那一个）， 现在不实现。这份文档提前写，是因为对方那边有等待时间—— 安排外部依赖不等于提前开发
